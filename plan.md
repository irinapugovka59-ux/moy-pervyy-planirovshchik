# План разработки «Планировщика Иры»

План основан на `tz.md`. Работа выполняется последовательно: следующий шаг начинается после того, как результат предыдущего шага работает и прошёл указанные проверки. Дополнительные функции, отсутствующие в ТЗ, не добавляются.

### Нюансы и добавления по ходу шага

- Первоначально для модулей использовались `.mjs` и `type="module"`. При ручной проверке выяснилось, что пользователь открывает `index.html` напрямую через `file://`, где Chrome и Safari блокируют загрузку локальных ES-модулей. Из-за этого календарь не отрисовывался.
- Для поддержки прямого открытия без сервера код переведён на отдельные классические `defer`-скрипты `.js` с единым пространством имён `PlannerIra`. Логическое разбиение по файлам сохранено, дублирования кода и сборщика нет. Это осознанное отступление от первоначального решения с нативными ES-модулями в пользу фактического сценария запуска пользователя.
- При проверке прямого открытия на ширине 1365 px обнаружено, что воскресенье уходило во внутреннюю горизонтальную прокрутку. Сетка скорректирована: на широком экране все семь дней каждой недели теперь видны одновременно.
- По итогам ручной проверки компоновка уточнена: следующая неделя располагается под текущей на всех ширинах экрана, а не справа от неё. Внутри каждой недели сохраняются семь дневных колонок на широком экране и вертикальный список дней на телефоне.
- Добавлен каталог `tests/` с автопроверками. Это не часть пользовательского интерфейса и не добавляет продуктовых функций сверх ТЗ.
- Заголовок недели вычисляется относительно текущей даты: при навигации исторический или дальний будущий период не получает ошибочную подпись «Текущая неделя».
- Визуальная оценка и проверка удобства остаются ручной частью приёмки этого шага.
